# Backend API

Node standard library only. JSON requests and responses under `/api`. All mutations require `Content-Type: application/json` and an Origin matching the configured host. Authentication uses an opaque HttpOnly, SameSite=Strict `be_session` cookie; the token is not exposed in JSON or stored in browser localStorage. The server stores only its SHA-256 hash. Visitor sessions expire after 14 days.

| Method | Path | Request / behavior |
|---|---|---|
| GET | /health | Service health |
| POST | /session | `{name}`; creates visitor session and cookie |
| DELETE | /session | `{}`; revokes session and leaves pending rooms |
| GET | /bootstrap | Safe challenge catalog, own rooms, public waiting teams, nearby checked-in visitors, own reports/rewards/preferences |
| POST | /checkin | `{code,area:1..4}` or `{leave:true}` |
| POST | /rooms | Team `{mode:"team",challengeId,name,capacity}` or Solo `{mode:"solo",challengeId}` |
| GET | /rooms/:id | Membership-filtered, role-filtered room state |
| POST | /rooms/:id/join | `{}`; checked-in visitor; capacity and block validation |
| POST | /rooms/:id/start | `{}`; host only, checked-in roster; locks attempt limit |
| POST | /rooms/:id/comment | `{text}`; once per member, private clue |
| POST | /rooms/:id/share | `{}`; explicitly shares own clue in Team |
| POST | /rooms/:id/messages | `{text,requestId}`; idempotent per sender |
| POST | /rooms/:id/guess | `{answer,requestId,expectedAttempts,agreement?,proposalId?}`; role/roster checks, atomic attempts/rewards; agreement required for Team; approved proposal required for Blind Eyes |
| POST | /rooms/:id/remove | `{targetId}`; Team host only; self removal rejected |
| POST | /rooms/:id/leave | `{}`; revokes membership; Blind departure ends round |
| POST | /match | `{challengeId,role:"guesser"|"describer"}`; same tag + opposite role; second online visitor creates a pending match; both members must accept before starting |
| POST | /rooms/:id/accept | `{}`; both online Blind members must accept before starting |
| POST | /rooms/:id/proposal | Guesser proposes; describer approves or rejects; see mutual confirmation below |
| GET | /chat/public | Public messages; outside gallery read-only |
| POST | /chat/public | `{text,requestId}`; checked-in sender |
| GET | /chat/:visitorId | Only this visitor's own DM pair |
| POST | /chat/:visitorId | `{text,requestId}`; checked-in, unblocked pair |
| POST | /preferences | `{action:"block"|"unblock"|"mute"|"unmute",targetId}` |
| POST | /reports | `{reason,details?,block?,roomId?,messageId?,channel?,targetId?}`; evidence resolved from stored message, not caller-supplied text |
| GET | /challenges/:id/fragment | Authenticated safe cropped JPEG |
| GET | /rooms/:id/artwork | Original image: active Blind describer or finished-room member only |
| GET | /events | SSE `connected`, `refresh`; invalidation only, no private payloads |
| GET | /admin/reports | Admin token required in `X-Admin-Token`; disabled unless configured |
| POST | /admin/reports/:id | Admin `{status:"resolved"|"dismissed",note}` |

Error body: `{error:"CODE"}`; HTTP 400 invalid input, 401 no session, 403 permissions, 404 missing resource, 409 stale state or conflicting room action, 413 large body, 415 content type, 429 rate limit.

Request IDs are generated by clients. Guess deduplication is scoped to room + user; additionally `expectedAttempts` must match before a new answer is accepted. This prevents two clients reading the same attempt count from charging two attempts. Synchronous service transactions serialize mutations inside one process. This is deliberately a single-process local store, not distributed transactional persistence.

Chat room histories keep the last 500 messages; chat reads return at most 200. Report evidence is copied at report submission and survives later history trimming. Bootstrap returns the last 30 own rooms. SSE reconnects periodically and the client has polling fallback. An SSE event never contains another user's room or message content.

## Original-interface compatibility

The current server uses `LegacyService` and serves the approved original UI byte-for-byte, with a separate `backend-bridge.js` script appended by the HTTP response. The bridge supplies real data and requested status, approval, location, and artwork-detail updates while retaining the original layout.

Additional routes:

- `POST /auth/register`: `{name,email,password}`. Creates a real account and session.
- `POST /auth/login`: `{email,password,remember}`. Login to the same account across devices; salted scrypt password verification; optional persistent cookie.
- `POST /auth/reset`: `{email}`. Generic preview response `{accepted:true,emailSent:false}`; SMTP is not configured.
- `POST /location`: `{state:"inside"|"outside"|"denied"|"unavailable"}`. Supports the original, explicitly labeled classroom demo buttons. Set `ALLOW_CLASSROOM_LOCATION=0` to reject the inside demo assertion on a public server.
- `POST /notebook`: `{draft?,lastCheckin?}`. Private per-user draft/check-in persistence, up to 16 MiB request body.
- `POST /friends`: `{targetId}`. Authenticated notebook contact.
- `POST /published`: existing creator draft fields plus `requestId,fragmentImage`. Server validates crop bounds, recomputes stars, saves image bytes, and publishes shared challenge metadata. Up to 16 MiB request body.
- `GET /uploads/u-<32 hex>.jpg`: authenticated uploaded image; active Blind guesser cannot fetch its target full image.

Bootstrap includes original challenge IDs (`legacyId`), original-compatible discovery history, private saved notebook, globally published challenges and own publication count. Room DTOs add `selfIndex`, own reflection (never another member's reflection), original IDs, stable member indices and clue-unlock count.

The approved original `data.js` remains a public catalog, exactly as supplied. It must not be described as a confidential answer vault; the room service still validates all submissions and protects private user content. The old static `/data.js` prohibition has therefore been removed intentionally to preserve the user's tested frontend. Private database files, original server source, accounts, password hashes and other users' reports are not served.

## Blind Eyes mutual confirmation

A real distinct account must select the same tag and complementary role with a heartbeat in the last 25 seconds. The page polls every 8 seconds while visible. A match enters `matched`; `POST /rooms/:id/accept` records each member's acceptance and starts only after both accept while present. Old unfinished simulation-era rounds require reconfirmation after restart.

`POST /rooms/:id/proposal` accepts `{action:"propose",answer,expectedAttempts}` from the guesser, then `{action:"approve"|"reject",proposalId}` from the describer. Proposing and rejecting use no attempts. The guesser submits the approved exact answer through `/guess` with `proposalId`, `expectedAttempts` and an idempotent `requestId`. Direct unapproved submissions are rejected. Room DTOs expose `proposal`, member `accepted/online`, and `lastSubmission` to both participants; result notifications interrupt typing deferral so both clients receive the same result, attempts and clues.

## Location verification during local testing

The original Allow Location button requests browser geolocation. Success posts `{state:"inside",source:"browser-geolocation"}` to `/location`, granting four hours of shared Team/chat access; denied/unavailable callbacks persist the corresponding restricted state. No coordinates are sent or stored. This is explicitly a testing access policy with no geographical boundary, not a server-verified 5 km geofence. Existing Inside Gallery test controls remain available when the browser location provider is unavailable.

## Artwork detail display

During an active Blind Eyes round, the describer interface renders the same selected crop as Borrow the Eyes. The guesser does not receive that image in the chat interface. Completed rounds retain the full-artwork reveal. This display rule does not change the original catalog or role checks on the full-image endpoint.
